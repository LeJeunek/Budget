# Bug Report: `/goals/[goalId]` (Savings Goal detail) never received Number Counters' `AnimatedNumber` treatment at all — its own list-view card did, and its Financial Goals detail-route counterpart did too

## Severity
**Medium** — no crash, no incorrect figure; every number displayed is still correct, just never animated. But Number Counters AC6 explicitly, by name, includes "`/goals`... **+ both detail routes**" as an in-scope surface, and the Definition of Done requires "every in-scope surface named in that capability's AC6 — all ten surfaces... each confirmed to animate." This route was missed in full — not a partial gap in one figure, but zero `AnimatedNumber` usage anywhere on the page — while the visually near-identical `goal-card.tsx` (rendered on the `/goals` list one click away) and the equivalent `/financial-goals/[goalId]` detail route both correctly animate the same class of figures. It is also the one concrete, live instance of the specific edge case this phase's own spec calls out by name (a goal's optional `plannedMonthlyContribution` transitioning to/from `null`) — and that edge case is untestable here today only because `AnimatedNumber` was never wired in to begin with.

## Component
- `src/app/(dashboard)/goals/[goalId]/page.tsx` (Server Component) — every currency figure (`goal.currentProgress`, `goal.targetAmount`, `goal.overageAmount`, `goal.remainingAmount`, `goal.plannedMonthlyContribution`) and the `ProgressRing`'s percentage label are all rendered via plain `formatCurrency`/`Math.round`, never `AnimatedNumber`.
- Contrast: `src/features/goals/components/goal-card.tsx` (rendered on `/goals`, the list this detail page is one click away from) — the identical class of figures (`goal.currentProgress`/`goal.targetAmount`, `ProgressRing`'s label) are correctly wrapped in `AnimatedNumber` (confirmed lines ~179–192).
- Contrast: `src/app/(dashboard)/financial-goals/[goalId]/page.tsx` — correctly reuses `FinancialGoalProgressBody` from `financial-goal-card.tsx` (which uses `AnimatedNumber`), so Financial Goals' own detail route inherits the animated treatment for free via component reuse. Savings Goals' detail page duplicates its own markup instead of reusing `goal-card.tsx`'s already-animated body, and that duplicated copy was never updated for Phase 5b.

## Summary
Number Counters AC6 names the in-scope surfaces explicitly: *"Goals and Financial Goals (`/goals`, `/financial-goals` + both detail routes, progress rings/bars and target/contributed figures)."* Both list pages (`/goals`, `/financial-goals`) and the Financial Goals detail route (`/financial-goals/[goalId]`) do receive the treatment. The Savings Goal detail route (`/goals/[goalId]`) does not — its own JSDoc even says it "otherwise mirrors structurally" the Financial Goal detail page, but that structural mirroring did not extend to the Phase 5b animation pass. Every headline figure on this page (the `ProgressRing`'s own custom percentage label, the current/target progress line, the overage-or-remaining line, and the optional planned-monthly-contribution line) renders through plain `formatCurrency`/`Math.round`, identically to how `goal-card.tsx` itself rendered before this phase.

This also means the product spec's own named edge case — *"A value transitions to/from `null` (e.g. a goal's optional planned monthly contribution being cleared)"* — has no live `AnimatedNumber` instance anywhere in the app to actually exercise: `goal.plannedMonthlyContribution` is rendered as an `AnimatedNumber` nowhere in the codebase (confirmed by grep — no `AnimatedNumber`/`plannedMonthlyContribution` co-occurrence anywhere in `src/`), even though this is the one field in the entire app the product spec calls out by name as the representative nullable-figure test case for this capability.

## Reproduction Steps
1. Sign in as the seeded e2e user and navigate to `/goals`.
2. Confirm a goal card's progress figure and ring percentage animate (count up) on load/update — they do, via `AnimatedNumber`.
3. Click into that same goal's detail page (`/goals/[goalId]`).
4. Inspect the page's rendered progress figures — the ring's percentage label, the "`$X of $Y`" line, and (if the goal has one set) the "Planned monthly contribution: `$Z`" line. None of these mount via `AnimatedNumber`; confirmed by source read (`page.tsx` lines 89–124) that every one of these is a plain server-rendered `{formatCurrency(...)}`/`{Math.round(...)}%` expression with zero Client Component counter involved.
5. Contrast with `/financial-goals/[goalId]` for any Financial Goal: the equivalent figures do mount via `AnimatedNumber` (confirmed via `financial-goal-card.tsx`'s `FinancialGoalProgressBody`, reused verbatim by that detail page).

## Expected Behavior
Per Number Counters AC6 ("Goals and Financial Goals... **+ both detail routes**") and the Definition of Done's "verified across every in-scope surface... all ten surfaces... each confirmed to animate," `/goals/[goalId]`'s headline currency/percentage figures should animate on mount and on value change, identically to `goal-card.tsx`'s own list-view rendering of the same underlying data and identically to `/financial-goals/[goalId]`'s equivalent detail route.

## Actual Behavior
`/goals/[goalId]` renders every headline figure through the pre-5b plain `formatCurrency`/`Math.round` path with no `AnimatedNumber` involvement anywhere on the page — a full, not partial, miss of one of AC6's ten named in-scope surfaces, and the one surface that happens to be this phase's own named representative test case for the null-transition edge case.

## Suggested Owner
Frontend Lead, `src/app/(dashboard)/goals/[goalId]/page.tsx`. The most maintainable fix is likely the same one already used to close the equivalent gap for Financial Goals: extract (or reuse, if a suitably-shaped one already exists) a `goal-card.tsx`-owned progress-body component analogous to `FinancialGoalProgressBody`, and have this page render that instead of hand-duplicating the figures — this would also collapse the current duplication between the two files' markup (`goal-card.tsx`'s own progress block vs. this page's near-identical copy), which is itself a pre-existing "avoid duplication" concern independent of Phase 5b. At minimum, each of the four currency figures and the `ProgressRing`'s custom label need to be wrapped in `<AnimatedNumber value={...} format={(n) => formatCurrency(n, userPreference.currencyDisplay)} />`, with the existing `goal.plannedMonthlyContribution !== null` guard kept exactly as-is ahead of that wrap (the correct, already-established null-handling pattern this codebase's other `AnimatedNumber` consumers already use).
